## 简介

**Stackable Potions Plus** 让原版药水从"一次性消耗品"变成真正可囤、可强化的战斗资源。

原版 Minecraft 中，药水每组只能放 1 瓶，喷溅药水带有 1 秒使用冷却，重复饮用同一种药水也只会刷新时长、不会变强。本模组针对这三点做了完整改造，并补齐了堆叠状态下的整套适配：

| 玩法 | 原版 | 本模组 |
|---|---|---|
| 药水堆叠 | 1 瓶 / 组 | **64 瓶 / 组**（普通 · 喷溅 · 滞留） |
| 喷溅 / 滞留药水 | 1 秒使用冷却 | **无冷却**，可连续投掷 |
| 重复获得同一种药水效果 | 只刷新时长，强度不变 | **时长累加 + 等级逐级提升** |
| 堆叠状态下饮用 | — | **只消耗 1 瓶，并正常返还玻璃瓶** |
| 酿造台操作 | — | 支持 Shift 快捷移动堆叠药水 |

在此之上，模组提供了完整的配置能力：等级上限、时长上限、无限时长、负面效果是否参与叠加、
瞬间效果连发增强等，全部可在配置文件中调整，注释为中文。

适合希望简化药水管理、或想要一套"越战越勇"式药水玩法的玩家与整合包。

- Minecraft **1.20.1**
- Minecraft Forge **47.x**（依赖声明为 `[46,)`，1.20.1 请用 47.1.0+）
- 不需要其它前置模组

## 配置说明

首次启动游戏后自动生成配置文件：

```
config/stackablepotionsplus-common.toml
```

文件内的注释全部为中文。修改后需**重启游戏**生效。

### 配置项一览

#### 1. 药水效果叠加设置（`effect_stacking` 分组）

| 键 | 默认值 | 取值范围 | 说明 |
|---|---|---|---|
| `maxAmplifier` | `4` | `0 ~ 127` | 效果可叠加到的最高等级。I 级 = 0，II 级 = 1，以此类推，**V 级 = 4**。**硬性上限 127（=128 级）**：原版在 amplifier 过高时跳跃提升等会出现无法跳跃的 bug，故叠加结果永不超过该值 |
| `durationCapSeconds` | `0` | `0 ~ 107374182` | 叠加后的总时长上限（秒）。`0` = 不限时（仅受游戏整数上限约束） |
| `infiniteDuration` | `false` | `true / false` | 开启后，叠加出的效果**永不衰减**（无限时长），不再受 `durationCapSeconds` 限制 |
| `stackNegativeEffects` | `false` | `true / false` | 是否允许负面效果（中毒、缓慢、虚弱、凋零等）也叠加等级与时长。默认关闭：负面效果保持原版行为（取更强/更久，不逐级叠加） |
| `enableInstantStacking` | `false` | `true / false` | 是否允许**瞬间效果**（瞬间治疗、瞬间伤害）在短时间内被连续施加时逐级增强。默认关闭 |
| `instantStackWindowSeconds` | `1.0` | `0.1 ~ 60.0` | 瞬间效果叠加的判定时间窗口（秒）。在该窗口内连续对同一目标施加同种瞬间效果，每次强度 +1，超过窗口则重新计数 |

#### 2. 使用冷却设置（`cooldown` 分组）

| 键 | 默认值 | 取值范围 | 说明 |
|---|---|---|---|
| `enableCooldown` | `false` | `true / false` | 为喷溅/滞留药水启用 1 秒（20 tick）使用冷却。默认关闭（模组已移除原版此限制） |

### 默认配置全文

```toml
[effect_stacking]
	#效果可叠加到的最高等级（amplifier），I级=0，II级=1，以此类推。V级=4
	maxAmplifier = 4
	#重复获得同种效果时，叠加后的总时长上限（单位：秒）。设为 0 表示不限时（仅受游戏整数上限约束）
	durationCapSeconds = 0
	#开启后，叠加的药水效果将永不衰减（无限时长），不再受 durationCapSeconds 限制。默认关闭
	infiniteDuration = false
	#是否允许负面效果（中毒、缓慢、虚弱等）也叠加等级与时长。默认关闭：负面效果保持原版行为（取更强/更久，不逐级叠加）
	stackNegativeEffects = false
	#瞬间效果叠加：允许治疗/伤害等瞬间效果（Instant Health/Damage）在短时间内被连续施加时逐级增强。默认关闭
	enableInstantStacking = false
	#瞬间效果叠加的时间窗口（单位：秒）
	instantStackWindowSeconds = 1.0

[cooldown]
	#为喷溅/滞留药水启用 1 秒（20 tick）使用冷却。默认关闭（模组已移除原版此限制）
	enableCooldown = false
```

## 机制详解

### 1. 效果叠加如何工作

当玩家（或生物）身上**已存在**某种药水效果，再次获得同一种效果时：

- **时长**：新获得的时长直接**累加**到剩余时长上（原版是"取两者中更长的一个"）。
  - 例如：力量药水效果剩 2:00，再喝一瓶（3:00）→ 变为 5:00。
  - 上限由 `durationCapSeconds` 控制，`0` 表示不限。
- **等级**：在已有等级与新获得等级**较高者基础上 +1 级**。
  - 例如：已有力量 I，再喝力量 I → 力量 II；已有力量 II，喝力量 I → 力量 III。
  - 上限由 `maxAmplifier` 控制，默认 `4` 即 V 级封顶；满级后继续喝只续时长、不再升。
- **无限**：若 `infiniteDuration = true`，叠加后的时长直接置为**无限**（游戏内 `duration = -1`，
  等价于指令 `/effect give ... infinite`），效果图标会显示为无限符号且永不衰减。

### 2. 负面效果默认不叠加

默认情况下（`stackNegativeEffects = false`），中毒、缓慢、虚弱等**负面效果保持原版行为**：
重复施加时只"取更强或更久"的版本，不会逐级叠加到夸张等级。

若想强化"泼毒 / 泼虚弱"的打法，把该开关设为 `true`，负面效果同样会累加时长、逐级升级
（配合 64 堆叠 + 无冷却，可以向怪群连续投掷，让中毒一路叠到 V 级）。

### 3. 喝药水返还玻璃瓶

饮用药水时，从堆叠中消耗 1 瓶并自动返还 1 个玻璃瓶，整组不会被一次性喝光或丢失。

### 4. 酿造台适配

酿造台支持快捷移动（Shift 点击）堆叠药水，堆叠的药水可以顺畅地放入 / 取出酿造槽位。

### 5. 瞬间效果短窗口叠加（默认关闭）

瞬间治疗 / 瞬间伤害这类效果**不走**"持续效果叠加"路径（它们一帧内结算完即消失），
所以上面的时间/等级叠加对它们不生效。若开启 `enableInstantStacking = true`：

- 在 `instantStackWindowSeconds`（默认 1 秒）内，**对同一个目标**连续施加同种瞬间效果，
  每次强度 +1（II → III → IV …）；
- 超过窗口或换了目标/效果则重新从该瓶药水自身等级开始；
- 结果同样受 `maxAmplifier` 与 128 级硬上限约束。

典型玩法：连泼数瓶瞬间伤害药水到同一怪物身上、或连喝瞬间治疗药水回血，逐次增强。
饮用、喷溅、滞留三种途径都会生效。

### 6. 高等级效果的等级显示

原版在**背包效果面板**里只把 1~10 级显示成罗马数字（I、II…X），**超过 10 级的等级文本会整个消失**。
本模组修复了这一点：10 级及以内保持罗马数字观感，**超过 10 级后直接显示阿拉伯数字**（如 11、25），
方便你把 `maxAmplifier` 调高后仍能看清实际等级。

## 常见问题

**Q：为什么我改了配置文件进游戏没变化？**
配置在游戏启动时读取，修改后需要重启游戏（单人游戏无需重进存档，重启游戏即可）。

**Q：`maxAmplifier` 能设多大？**
最高可设到 `127`（即 128 级）。这是**硬性上限**：原版效果在 amplifier 过高时会出现 bug
（典型症状：跳跃提升等级过高时玩家完全无法跳跃），所以叠加结果无论如何不会超过 128 级。
1~10 级会以罗马数字显示，超过 10 级本模组会以阿拉伯数字显示等级，数值等级照常生效。

**Q：堆叠数量能改吗？**
不能。药水堆叠固定为 64（原版普通物品默认堆叠即 64）。
曾经提供过堆叠数量配置项，但因该配置的注入时机早于配置文件加载、修改无法生效，已移除。

**Q：和哪些模组可能冲突？**
本模组通过 Mixin 修改了原版的物品注册与药水效果合并逻辑。若其它模组也修改了
`Items` 静态注册、`MobEffectInstance.update` 或药水相关 GUI，可能存在冲突。此类冲突通常表现为
启动报 Mixin 注入失败（日志中会出现 `Mixin apply failed`），如有问题请提供日志排查。

**Q：服务端 / 客户端都要装吗？**
本模组修改的是**注册期物品属性**与效果合并逻辑，属于需要双方数据一致的改动。
**联机时：服务端与客户端都应安装**，否则可能出现物品堆叠 / 数据不同步异常。
单人游戏只需本机安装即可。

**Q：`durationCapSeconds` 为什么要设成 0 而不是一个大数？**
`0` 表示"不设上限"，此时叠加时长只受游戏 int 上限约束（约 21.4 亿 tick，实际不可能达到）。
若你希望"叠加不超过 N 秒"，填入具体秒数即可。
